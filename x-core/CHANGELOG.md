# Changelog

All notable changes to `x-core` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

`x-core` is released in lockstep with the other gems of the [x-ruby](https://github.com/sferik/x-ruby) repository, at one version across `x-core`, `x-uploader`, `x-objects`, and `x`. This file holds the changes to the HTTP layer; [the changelog of the repository](https://github.com/sferik/x-ruby/blob/main/CHANGELOG.md) holds the changes to every gem.

## [1.0.0] - 2026-09-25

The first release of `x-core`, which 1.0.0 split out of the `x` gem. The entries below are the changes since `x` 0.19, the last release before the split; see [UPGRADING.md](https://github.com/sferik/x-ruby/blob/main/UPGRADING.md) for the changes that code written for 0.19 needs.

### Added
* Read the response of one request where the request is made: `get`, `post`, `put`, and `delete` take a block, which receives the `X::Response` of each response that request gets, so the rate limit it spent, the headers it carried, and the resources the API billed it for read beside the call rather than out of the `on_response` of the client, which every request of that client reports to; the block is passed what the hook is passed, at the same points, a response the API refused among them, before the error is raised, and each attempt of a request that was sent again, and a request that has both reports to the hook of the client first, both receiving the one summary
* Compare one release with another with `X::Core.gem_version`, which builds the `Gem::Version` of the `VERSION` the gem holds
* Send headers with every request a client makes, and every stream it opens, with the `headers:` of `X::Client.new`, named by a String or a Symbol, as the signatures type them, such as one that names the application in the `User-Agent`; they are defaults, so a header of the same name passed to a request is sent in place of the client's, and each of the client's is sent in place of a default of the gem, a copy of a client keeps them, and a redirect to another origin drops the ones that carry credentials, as it does for a header passed to a request
* Split the gem into gems released in lockstep: `x-core` (the HTTP client), `x-uploader` (media, profile image, and banner uploads), `x-objects` (resource objects), and `x` (a meta-gem that depends on all three and mixes the object methods into `X::Client`); `x-uploader` and `x-objects` depend on `x-core`, which declares `X::Error`, the base class of every error the gems raise; every class a caller writes is named directly under `X`, whatever gem declares it, and each gem's module holds its own mixins and internals, apart from `X::Objects::Error` and `X::Uploader::Error`, the two names a rescue reaches for to catch the failures of one gem alone, though `x-objects` makes no request of its own and asks the client it is given to make them; each gem depends on the ones it needs with a pessimistic constraint on the version being released, so the lockstep holds while a patch of `x-core` still installs under the gems of the same minor
* Pass a resource class, such as `X::User`, as the `object_class` of any request to build objects from the response, or an array of them from a list; a client passes the parsed body and itself to any `object_class` that responds to `from_response`, and the objects it builds hydrate to the full resource, since a request may have asked for only some fields
* Pass query parameters to `get`, `post`, `put`, `delete`, and `stream` as `params:`, which drops nil values, joins arrays with commas, and sends a `Time` in UTC in the ISO 8601 form the API takes, so callers no longer build query strings by hand
* Encode a body passed to `post` or `put` that is not a String, such as a Hash or an Array, as JSON, and encode `form:` fields as a form body with the matching content type; a request given both a body and form fields raises `ArgumentError`, since it sends one body
* Authenticate as an app when a client is given an `api_key` and `api_key_secret` without access tokens: `X::AppOnlyAuthenticator` fetches a bearer token with the client credentials grant on the first request and keeps it
* Copy a client with some options changed with `X::Client#with`, such as `client.with(base_url: "https://api.x.com/1.1/")` for the v1.1 API or `client.with(access_token: nil, access_token_secret: nil)` for an app-only client; a copy given no OAuth 2.0 credential the client does not hold shares the OAuth 2.0 authenticator of the client it was copied from, however the tokens change while it is built, so neither brings back a refresh token X no longer accepts, an `expires_at` given to such a copy is set on the authenticator they share, `X::Client#expires_at` reads the expiration of the last refresh, and a copy given other OAuth 2.0 credentials builds an authenticator of its own, whose refreshes the `on_token_refresh` of the client it was copied from no longer receives
* Add `inspect` to `Client` and the authenticators that never reveals credentials
* Preserve custom headers passed to `get`, `post`, `put`, and `delete` across redirects
* Pass an `X::Response` to the `on_response` of a client after every request, and for each object a stream delivers, which counts the resources the response returned with `resource_counts` and reads its rate limits with `rate_limits` and `rate_limit`
* Read the headers of a response with `X::Response#headers` and `X::HTTPError#headers`, a frozen Hash whose names are lowercase, whatever case the API sent them in, and whose repeated fields are joined with a comma, as HTTP joins the lines of one; `http_response` is left as the escape hatch for what neither of them reads, the `Net::HTTPResponse` the client received
* Retry a request refused for a rate limit after the wait the refusal asks for, up to `max_rate_limit_retries` times, which is 0 by default, for a wait no longer than `max_rate_limit_wait` seconds, which is 900 by default; a refusal that asks for no wait, and reports no limit that resets, waits a minute, doubling for each retry after; up to five seconds are added at random to each wait, since every request of an app shares the app's limits, and so the moment they reset, and they are added to the wait rather than taken off it, since a request sent before the limit resets is refused again, so `max_rate_limit_wait` is the longest reset a request waits for
* Refresh an OAuth 2.0 access token when it expires, given the `expires_at:` of `X::Client`, a `Time`, since anything else raises `ArgumentError`, or when the origin of the base URL rejects it with 401 Unauthorized, sending the request again with the new token, unless a refresh issued the token less than a minute ago, which has not expired, so an endpoint that always rejects the token spends no refresh token on each request, and forgetting the expiration time when a refresh reports no lifetime, rather than refreshing again on every request; a 401 from another origin, which a request that names a URL of its own or is redirected there reaches without the token, refreshes nothing, since X accepts a refresh token once; a lock lets requests on several threads refresh once, and the `on_token_refresh:` of the client, or of `X::OAuth2Authenticator`, receives the authenticator after each refresh to store its tokens, once the refresh has released its lock, so the callable can send a request with the client, such as looking up the user whose tokens it stores, as does the `on_token_refresh` of each copy of the client that shares its authenticator, once for each distinct callable; the authenticator a client builds holds no callable of its own, so its `on_token_refresh` is nil, and the hooks are read from the clients
* Read the status of an `X::HTTPError` as an Integer with `status`, as `X::Response#status` reads it, and read what the API said about the request without reaching into its response: `body` is the body as it arrived, and `problem` an `X::Problem` describing the failure, which is the first error the body names, or the problem it describes itself, so a problem reads the same whether the API refused the request or answered it and named what it could not return; the Net::HTTP response itself is `http_response`, on `X::HTTPError`, `X::InvalidResponse`, and `X::RateLimit` alike, which is the name `X::Response` reads it by
* Raise an error of its own for four more statuses: `X::MethodNotAllowed` (405), `X::RequestTimeout` (408), `X::UnsupportedMediaType` (415), and `X::UnavailableForLegalReasons` (451), each an `X::ClientError` as the statuses beside them are, where a 4xx the errors did not name raised `X::ClientError` itself, which says only that the request was refused
* Name the request an error was raised for: `X::HTTPError`, `X::NetworkError`, and `X::InvalidResponse` read its `http_method` and `uri`, as `X::Response` reads them, and their message names it, as `GET /2/users/1: Could not find user` does, so a log of failures says which endpoint each one came from without any code to add it; the message leaves the query out, since the object layer asks for every field of a resource, which makes a query longer than the rest of the message, while `uri` keeps it, and a request that was redirected is named by the request that was made, which is the one `on_response` reports
* Read and change the rules of the filtered stream with `stream_rules`, `add_stream_rules`, and `delete_stream_rules` on `X::StreamingClient`, which authenticate as the app as a stream does; a rule to add is a Hash of a value and the tag it is labelled with, or a String, which is the value of a rule with no tag, and a rule is deleted by its identifier, which a rule the API returned, a Hash holding an `id`, or an Integer names, or by the value it matches, which a Hash holding a `value` and no identifier, or a String, names, so what was read deletes itself and what was added deletes what it added, with `dry_run: true` to have the API check the rules and change none of them, and `stream_rules` takes its query parameters as `params:`, as `get` does, and reads every page of the rules; `add_stream_rules` returns the rules it added and yields each rule the API did not add, such as one the app already has, as the `X::Problem` the API reported; no rules add or delete none, and send no request, and anything else raises `ArgumentError`
* Read the user a client's credentials act for without a request with `X::Authenticator#user_id`, which is the identifier an OAuth 1.0a access token begins with and nil for credentials that name no user, and tell two OAuth 2.0 authenticators apart with `X::OAuth2Authenticator#same_credentials?`, neither of which hands out a secret to do it
* Keep connections open between requests to the same host, up to eight idle per host and for the 30 seconds of `keep_alive_timeout`, a setting of `X::Client` and `X::Connection`, which X holds an idle connection well beyond, and which a client behind a proxy that closes idle connections sooner can lower, rather than the two `Net::HTTP` keeps one by default, so a request no longer opens a TCP and TLS connection of its own; a connection whose request fails is closed, `X::Connection#close` closes the idle ones, and a forked process opens its own and leaves its parent's open when it closes them; `X::Client#close` closes the connections a client keeps open, and those of its app-only copy, and a later request opens one again
* Authenticate as the app with `X::Client#app_only`, a copy of a client that authenticates as a user, signing with OAuth 1.0a or with OAuth 2.0, which holds the app's bearer token, the one the client was given or one it fetches once with the app's API key and secret, and which the client returns again, with the connections it keeps open, since its credentials and settings never change; threads that ask for the copy together get one copy, and fetch one token; a client that authenticates with OAuth 2.0 as a user and holds neither the app's bearer token nor its API key and secret raises `X::UnsupportedOperation`, an `X::Error` that code depending on `x-core` alone can rescue by name, and which the object layer raises for anything the API offers no way to do, rather than return itself and send a user's credentials to an endpoint that refuses them, and a stream such a client opens raises it too, before it connects
* Stream with app-only authentication from a client that signs with OAuth 1.0a, since the stream endpoints refuse it
* Stream with `X::StreamingClient`, which `X::Client#streaming` builds from a client, sharing its credentials, base URL, parsing classes, and `on_response` hook while keeping the settings of a long-lived connection, which it keeps for as long as it lives, so a stream that runs for hours never reads a setting another thread is halfway through changing: `X::Client#streaming` takes the `read_timeout:` and `max_reconnects:` that differ, and a stream that connects differently is opened from a copy of the client, as in `client.with(open_timeout: 2).streaming`; `stream` raises `ArgumentError` when given no block, before it opens the stream, rather than after reading the first object, which the API bills
* Stop a stream from the block that reads it: a `break` stops it and answers what it was given, a `throw` unwinds past it, and an error raised by the block, by `on_response`, or by the class that builds each object stops it and reaches the caller, a `StopIteration` included, which the loop that reconnects a stream used to swallow
* Reconnect a stream that ends or drops, or that delivers a line that is not JSON, which raises `X::InvalidResponse` rather than `JSON::ParserError`, backing off as X recommends, up to the `max_reconnects` of the streaming client, which is unlimited by default; a rate limit waits as long as it asks, or from a minute, doubling each attempt
* Read a stream with the `read_timeout` of the streaming client, 30 seconds by default, half again the 20-second interval of the keep-alive X sends, so a stream that goes quiet reconnects rather than waiting for the timeout of an ordinary request
* Refresh the tokens of a public OAuth 2.0 client, such as a native or single-page app, given a `client_id`, `access_token`, and `refresh_token` without a `client_secret`; the refresh sends the client ID in its body rather than authenticating with a secret
* Authorize an app to act for a user with the OAuth 2.0 authorization code flow and PKCE: `X::OAuth2Authorization` builds the URL that asks the user, with a state and code verifier to store until X redirects back, and exchanges the code of the redirect for `credentials` or a `client`, raising `X::AuthorizationError`, whose `error_code` is the OAuth 2.0 error code, when the user declines, the state does not match, X refuses the code, or the redirect is not a valid URL; a nil or empty state raises `ArgumentError`, since it would accept the redirect of any authorization
* Read what a successful response held instead of JSON with `X::InvalidResponse#body`: the body of a response, or the line of a stream, whose response cannot be read for its body once the stream is open; and its status and headers with `status` and `headers`, as `X::HTTPError` reads those of a refused one
* Tell the rate limits a refusal reports that are used up from the one a request must wait for with `X::TooManyRequests#exhausted_rate_limits` and `#limiting_rate_limit`
* Read the defaults of the settings a client takes from the client: `X::Client::DEFAULT_MAX_REDIRECTS`, `X::Client::DEFAULT_MAX_RATE_LIMIT_RETRIES`, `X::Client::DEFAULT_MAX_RATE_LIMIT_WAIT`, and `X::Client::DEFAULT_MAX_RETRIES`, and `X::Connection::DEFAULT_KEEP_ALIVE_TIMEOUT`, beside the `DEFAULT_BASE_URL`, `DEFAULT_ARRAY_CLASS`, and `DEFAULT_OBJECT_CLASS` it had, and `X::StreamingClient::DEFAULT_MAX_RECONNECTS` beside its `DEFAULT_READ_TIMEOUT`, so that no default is read from a class that is internal to x-core
* Ship this changelog with `x-core`, holding the entries of the changelog of the repository that are changes to `x-core`, which the `changelog_uri` of its gemspec names
* Send a request again after the API failed to answer it, or after its answer never arrived, with the `max_retries:` of `X::Client.new`, which is 2 by default, where `max_rate_limit_retries` is 0, and which is 0 for a client that raises at once; a `GET`, `PUT`, or `DELETE` that raises an `X::ServerError` or an `X::NetworkError` is sent again, waiting up to a second before the first retry and up to twice as long before each retry after, a random share of up to half of each wait taken off, since a failure of the API fails every request in flight at once, and requests that waited the same time would be sent again together, and each attempt builds its request afresh, so it is signed anew and its response reaches `on_response`; a `POST` is never sent again, since the API may have acted on one whose answer never arrived, and a 4xx is raised at once, since the request is the reason for it; a response that carries a `Retry-After` header, such as a 503 that names the time its endpoint is expected back, is waited out for as long as it asks, or for the backoff of the attempt, whichever is longer, and one that asks to be left alone for longer than a minute raises at once rather than hold the caller
* Raise `ArgumentError` from `X::Client.new`, `X::Client#with`, and `X::Client#streaming`, when the client or stream is built, for a `max_redirects`, `max_rate_limit_retries`, or `max_retries` that is not an Integer of at least 0, a `max_rate_limit_wait` that is not a number of seconds of at least 0, or a `max_reconnects` that is neither an Integer of at least 0 nor `Float::INFINITY`, naming the setting and what it was given, such as a String read from an environment variable, rather than from the comparison of the first failure that reached it
* Describe what the API said of a request with `X::Problem`, which reads its `title`, `detail`, `type`, `resource_type`, `resource_id`, `parameter`, `value`, and `message`, and writes itself as JSON with `as_json` and `to_json`, and which `X::HTTPError#problem` answers and `x-objects` reports for a successful response

### Changed
* Hold `VERSION` in a String, where it held a `Gem::Version`, since a version constant is a String throughout Ruby: what reads one splits it, matches it, or sends it where a String belongs, such as the release a crash reporter is told; `gem_version` builds the `Gem::Version` that compares it with another version
* Require Ruby 3.4 or later
* Keep the credentials that are secrets private, on a client and on the authenticator it hands out: `api_key_secret`, `access_token`, `access_token_secret`, `bearer_token`, `client_secret`, and `refresh_token` no longer read off a client, and `api_key_secret`, `access_token_secret`, `client_secret`, and the `bearer_token` of an `X::BearerTokenAuthenticator` or an `X::AppOnlyAuthenticator` no longer read off an authenticator, so nothing that reflects over either reads a credential out of it, as `inspect` reveals none; `api_key`, `client_id`, and `expires_at` remain public on a client, since none of them is a secret, as do `access_token` and `refresh_token` on an authenticator, which is how the hook given to `on_token_refresh` stores the tokens of a refresh, and `with` carries every credential to a client derived from one
* Keep the proxy of a client, a streaming client, and a connection to itself, since a proxy URL can hold the user and password of the proxy: `proxy_url` no longer reads off `X::Client`, `X::StreamingClient`, or `X::Connection`, and `proxy_uri`, `proxy_host`, `proxy_port`, `proxy_user`, and `proxy_pass` no longer read off a connection; `inspect` summarizes the proxy URL without its user and password, and `with` and `streaming` carry the proxy to a client derived from one
* Carry the credentials of a client to the origin of its `base_url` alone: an endpoint, or a stream, that names a whole URL of another scheme, host, or port is sent there without the `Authorization` header its authenticator signs, and without any `Authorization`, `Cookie`, or `Proxy-Authorization` header of the client or the request, as a redirect that leads off the origin already was; an endpoint of another version of the API, such as `https://api.x.com/1.1/account/settings.json` under the default `base_url`, shares that origin and carries them as it did, whatever case its host is written in, and a client built with another `base_url` carries them to that origin, since that is the origin they were given for
* Open a connection with a 10-second timeout rather than 60: opening one is a TCP handshake and a TLS one, which a reachable host finishes in well under a second, so a host that is not answering is given up on rather than held for a minute; `read_timeout` and `write_timeout` are 60 seconds still, since an endpoint may be slow to answer
* Read only the rate limits a response reports in full, with a limit, remaining requests, and reset time, so `X::TooManyRequests#retry_after` no longer raises `KeyError` for a response without a reset time
* Wait as long as a failed response asks in `X::HTTPError#retry_after`, which reads the `Retry-After` header of any response the API refused, counted in seconds or named as an HTTP date, and nil for one that carries none; `X::TooManyRequests#retry_after` reads it and falls back on `#reset_in` for a refusal that carries no header, where it was an alias for `#reset_in`; the header counts from when the response was sent, so the wait is right however far this machine's clock is from the API's, and it answers for a refusal that reports no limit at all, which `#reset_in` leaves nil; the retries of `X::Client` and the reconnects of a stream wait for it
* Send requests to `api.x.com` rather than `api.twitter.com` by default, the host of the token endpoints, the uploads, and the API's documentation
* Rename `X::ConnectionException`, the error for 409 Conflict, to `X::Conflict`, after its status like every other HTTP error
* Rename the `response` of `X::HTTPError` and `X::RateLimit`, which holds the Net::HTTP response, to `http_response`, the name `X::Response` reads it by, so that one name means one thing across the gems
* Rename `X::OAuthAuthenticator` to `X::OAuth1Authenticator`, beside `X::OAuth2Authenticator`
* Move the HTTP client into `x-core`, under `lib/x/core`, and the uploaders into `x-uploader`, under `lib/x/uploader`
* Wrap every network failure in `NetworkError`, so a stream reconnects after it rather than stopping: `IOError`, which includes `EOFError`; `SystemCallError`, which includes every `Errno` error, such as `Errno::ECONNABORTED` and `Errno::ENETDOWN`; `Timeout::Error`, which includes `Net::WriteTimeout`; `Net::ProtocolError`, which a proxy that refuses to open a tunnel raises; `Zlib::Error`, for a compressed body cut off mid-response; `Net::HTTPBadResponse`; and `SocketError`, which a host that cannot be resolved raises
* Stop following redirects after exactly `max_redirects` hops instead of one more, so a `max_redirects` of 0 follows none and raises `X::TooManyRedirects` for each redirect that could be followed, while one that cannot, such as 304 Not Modified, is returned for the client to raise an `X::HTTPError` for, however many came before it
* Sign OAuth 1.0a requests with the [simple_oauth](https://github.com/laserlemon/simple_oauth) gem, in place of the signing code `X::OAuthAuthenticator` carried; it keeps the same credentials and produces the same header
* Build and parse the OAuth 2.0 token refresh with simple_oauth, in place of the request and response handling `X::OAuth2Authenticator` carried; it sends the same request
* Refresh the tokens of `X::OAuth2Authenticator` at once with `refresh!`, in place of `refresh_token!`, which sat beside the `refresh_token` reader as though it were its bang form; it answers the authenticator, which holds the new tokens, rather than the Hash of the token response, whose shape was the one the code that parsed it built
* Raise `ArgumentError` from `X::Client.new`, and so from `with`, for credentials that do not form a complete set, instead of sending requests without credentials, or authenticating as the app when an access token lacks its secret, and for any credential that belongs to no complete set, such as a `client_id` or an `api_key` beside a `bearer_token`, instead of ignoring it, while a client may hold several complete sets, and an `expires_at` beside any; a credential that is an empty String, as `ENV.fetch("X_BEARER_TOKEN", "")` reads a variable that is not set, raises `ArgumentError` as well, instead of sending an `Authorization` header that authenticates nothing
* Raise `X::InvalidResponse`, an `X::Error` that holds the response, for a successful response whose body is not JSON, such as the page of a proxy or captive portal, instead of returning nil as though the response had no body; a successful response without a body still returns nil
* Move `stream` from `X::Client` to `X::StreamingClient`, so that the client carries no streaming settings
* Raise `X::AuthorizationError`, an `X::Error`, when X refuses to refresh an OAuth 2.0 token or to issue an app-only bearer token, rather than a bare `X::Error`, with the OAuth 2.0 `error_code`, such as `invalid_request` for a refresh token that was revoked or already used, and the HTTP `status` of the refusal; a token endpoint that fails to answer, with 429 Too Many Requests or a server error, refuses nothing, so it raises the `X::TooManyRequests` or `X::ServerError` a response of the API with that status raises, which a client waits out or sends again as it does that response, rather than an `X::AuthorizationError`, which tells a caller to ask the user to authorize the app again
* Return nil from `X::TooManyRequests#reset_at`, `#reset_in`, and `#retry_after` when the response does not say when the limit resets, instead of `Time.at(0)` and 0, which told a caller to retry at once
* Mark `X::Connection#perform` and `#perform_stream`, which take a `Net::HTTPRequest`, as `@api private`, the internals through which `X::Client` sends requests, so that they can change within 1.x
* Resolve an endpoint that begins with a slash against the base URL, like one without, so `client.get("/users/me")` requests `https://api.x.com/2/users/me` rather than drop the `/2/` of the API version and request a page that is not found; pass a whole URL to reach another path of the host
* Send each request once, turning off the retry that `Net::HTTP` makes by itself of a GET, PUT, or DELETE request after a timeout or a dropped connection, which sent the OAuth 1.0a nonce and signature of the first attempt again and could repeat a read the API bills; such a failure raises `X::NetworkError`, and the caller decides whether to send the request again
* Name the token endpoint of `X::OAuth2Authenticator` `TOKEN_URL`, as `X::AppOnlyAuthenticator` and `X::OAuth2Authorization` name theirs, in place of `TOKEN_HOST` and `TOKEN_PATH`
* Report every rate limit a response names from `X::TooManyRequests#rate_limits`, as `X::Response#rate_limits` does, rather than the exhausted ones alone, and read the 15-minute limit from `X::TooManyRequests#rate_limit`, as on `X::Response`, rather than the exhausted limit that resets last, which is now `#limiting_rate_limit`; `reset_at`, `reset_in`, and `retry_after` still wait for that limit, so a 429 that names an exhausted 24-hour limit beside a 15-minute limit with requests left still waits for the 24-hour one
* Make the constants that hold a message, a pattern, or an internal default of x-core private, so that they can change within 1.x: `X::HTTPError::JSON_CONTENT_TYPE_REGEXP`, `X::Connection::NETWORK_ERRORS`, and `X::OAuth2Authenticator::EXPIRATION_BUFFER`, and remove `X::Connection::DEFAULT_HOST` and `DEFAULT_PORT`, since every request names its host
* Mark `X::RateLimit.new`, `X::RateLimit.reported?`, `X::HTTPError.new`, `X::InvalidResponse.new`, `X::Response.new`, and `X::Authenticator#header`, which take the `Net::HTTP` response or request of a request, as `@api private`, so that they can change within 1.x as those objects may; the `response` and `http_response` they are built from stay public
* Name the classes and modules that are internal to x-core under `X::Core` rather than directly under `X`, and mark them `@api private`, so that the flat namespace holds the interface alone and they can change within 1.x; they are the internals of `X::Client` and `X::StreamingClient`, whose settings expose them: `X::Core::RequestBuilder`, `RedirectHandler`, `ResponseParser`, `StreamParser`, `RateLimitHandler`, `ReconnectHandler`, `ConnectionPool`, `ConnectionProxy`, `CredentialValidator`, `TokenEndpoint`, `RequestEncoding`, `StreamCallbackError`, and the `ClientAppOnly`, `ClientCredentials`, `ClientSettings`, and `ClientTokenRefresh` mixins of the client; `X::Client`, the authenticators, `X::Connection`, `X::StreamingClient`, `X::OAuth2Authorization`, `X::Response`, `X::RateLimit`, and every error keep the names they had
* Name the gem in the `User-Agent` header of every request, as `x-ruby/1.0.0 ruby/3.4.0 (arm64-darwin24)`, where it named `X-Client`, which is the name of no gem
* Send an idempotent request again, on a connection opened for it, when the connection it was sent on was one the client had kept open and X, or a proxy between, had closed while it was idle, which the request learns as it is written or its response is first read, as `EOFError`, `ECONNRESET`, `ECONNABORTED`, or `EPIPE`; such a request never reached the API, so nothing is repeated, and it no longer raises `X::NetworkError` for a connection that had gone stale, while a request that fails any other way, such as by timing out, is not sent again by the connection, since the API may have acted on it, and is left to the retries of the client
* Document every error class of `x-core` the same way, saying what X sends each status for, and draw the whole hierarchy on `X::Error`, so that the class to rescue can be found in one place

### Removed
* Remove `X::HTTPError#code`, which read the status as the String `"404"` that Net::HTTP reads; `#status` reads it as the Integer `404`, as `X::Response#status` does, and `error.http_response.code` still holds the String
* Remove `X::HTTPError#error_message` and `#message_from_json_response`, which built the message an error is initialized with, which `message` returns, and make `#json?` private
* Remove `X::OAuthAuthenticator::OAUTH_SIGNATURE_ALGORITHM`, which named the digest of the signing code that is gone, and `OAUTH_VERSION` and `OAUTH_SIGNATURE_METHOD`, which nothing read once simple_oauth signed requests
* Remove `X::OAuth2Authenticator::REFRESH_GRANT_TYPE`, which named the grant type simple_oauth now sends
* Remove the `base64` dependency from `x-core`, which encodes no Base64 of its own now that simple_oauth builds the Basic credentials
* Remove `X::RateLimit#retry_after`, an alias for `#reset_in`, which read the reset time of a limit where `X::TooManyRequests#retry_after` reads the `Retry-After` header of the refusal, so one name answered a request with two waits; read `#reset_in`, which says what it reads
* Remove the setters of `X::RateLimit`, `X::BearerTokenAuthenticator`, `X::OAuth1Authenticator`, and `X::OAuth2Authenticator`, whose attributes are now read-only; derive a client that holds another credential with `X::Client#with`, which builds a new authenticator, and a token refresh replaces the tokens of an OAuth 2.0 authenticator under its lock
* Remove the setters of `X::Client`: `api_key=`, `api_key_secret=`, `access_token=`, `access_token_secret=`, `bearer_token=`, `client_id=`, `client_secret=`, `refresh_token=`, `base_url=`, `default_array_class=`, `default_object_class=`, and the delegated `open_timeout=`, `read_timeout=`, `write_timeout=`, `proxy_url=`, `debug_output=`, and `max_redirects=`; a client keeps the credentials and settings it was built with for as long as it lives, so a request never signs with a mix of old and new credentials and never runs against a setting another thread is halfway through changing, and `with` derives a client that differs, checking its credentials as `X::Client.new` does
* Remove the setters of `X::Connection`, `open_timeout=`, `read_timeout=`, `write_timeout=`, `proxy_url=`, and `debug_output=`, for the reason the setters of `X::Client` are gone; a connection keeps the settings it was built with for as long as it lives

### Fixed
* Declare the libraries the signatures of `x-core` refer to in `sig/manifest.yaml`, `simple_oauth` and the standard libraries, such as `net-http`, `uri`, and `openssl`, so `rbs collection` loads them for code that depends on it
* Resolve a relative redirect against the URL of the request it redirects, rather than the base URL, so a redirect from a request to another host, such as `upload.x.com`, stays on that host with its credentials
* Build the message of an `X::HTTPError` from a body that is not the JSON its content type claims, such as an empty or HTML body, or whose errors have no `message`, instead of raising `JSON::ParserError`, `KeyError`, or `TypeError` in place of the error, so a stream reconnects and a chunk upload retries after such a server error; an error without a `message` gives its `detail` or `title`
* Refresh an OAuth 2.0 token over the connection of the client that sends the request, rather than a connection of the authenticator's own, so the proxy, timeouts, and debug output of a client apply to a token refresh as they do to every other request, those of a copy given others with `with` among them, though the copy shares the authenticator of the client it was copied from
* Drop the credentials, and any `Authorization`, `Cookie`, or `Proxy-Authorization` header passed in `headers:`, named by a String or a Symbol in any case, when a redirect leads to another scheme, host, or port, so a redirect cannot send them to a host they were not meant for; a 307 or 308 still replays the request body to the new host
* Send no `Authorization` header from a client without credentials, rather than an empty one
* Send a `Content-Type` header with a request that carries a body alone, rather than with every request, so a `get` or a `delete`, and a `post` to an endpoint that takes no body, such as the finalize of a chunked upload, no longer names the type of a body it does not send; a body is still sent as JSON unless the caller's headers, or the `form:` of a request, name another type
* Raise `X::ClientError` or `X::ServerError` for a 4xx or 5xx status that no error class names, such as 405 or 501, instead of `X::HTTPError`, so a stream reconnects and a chunk upload retries after any server error
* Link each gem's `changelog_uri` to the `main` branch, which the repository uses, rather than `master`
* Send the authenticator on every redirected request, not only the first
* Sign a form-encoded request body, which OAuth 1.0a requires and the signature left out, so such a request no longer fails to authenticate
* Sign a query parameter that repeats once per value, rather than signing only one of the values
* Sign the normalized URL, so a request to a host with no path signs the `/` the server sees
* Form-encode the client credentials before Basic authentication on token refresh, as RFC 6749 Section 2.3.1 requires, so a client ID or secret containing a reserved character authenticates
* Leave the user and password of a proxy out of the message of an invalid proxy URL, and out of `X::Connection#inspect`, which now summarizes the proxy URL and timeouts; and raise `ArgumentError` rather than `URI::InvalidURIError` for a proxy URL that cannot be parsed
* Decode a percent-encoded proxy user and password, which were sent to the proxy still encoded
* Connect to an `https://` proxy over TLS, rather than sending it the host to tunnel to and the proxy user and password in plaintext
* Raise `X::HTTPError` for a redirect that cannot be followed, such as 304 Not Modified or one whose location is missing, is not a valid URL, or is not an HTTP or HTTPS URL, instead of `KeyError`, `URI::InvalidURIError`, or `ArgumentError`
* End a `base_url` without a trailing slash with one, so that `base_url: "https://api.x.com/2"` sends a request for `users/me` to `/2/users/me` rather than `/users/me`
* Raise the error that a client's `on_response` hook, or the `object_class` that builds each object of a stream, raises, rather than take it for a network error and reconnect until the reconnects run out, re-reading objects the API bills; a socket that drops still reconnects, as does a line that is not JSON
* Connect to a host named by an IPv6 literal, such as a `base_url` of `http://[::1]:8080/`, which raised `X::NetworkError`, and to a proxy named by one; the net-http 0.6 that Ruby 3.4 ships cannot request such a host, so `x-core` depends on net-http 0.8 or later
* Take the proxy of a request from the variable of the environment that names one for its scheme, `https_proxy` for the HTTPS requests these gems make and `http_proxy` for plain HTTP, and reach a host that `no_proxy` names directly, for a client given no `proxy_url`; `Net::HTTP`, which resolved the proxy before, reads `http_proxy` alone whatever the scheme, so a proxy named in `https_proxy` reached nothing and one named in `http_proxy` carried every request to the API
* Declare `X::BadGateway` and `X::GatewayTimeout` as `X::ServerError`s in the signatures, as the classes always were, where the signatures declared them `X::ClientError`s, so code that rescues `X::ServerError` type-checks against the hierarchy the gem raises
